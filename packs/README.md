# Data packs

Built-in ticket forms load through the same pack format that Steam Workshop items will use.
A pack is a folder of **data only**: a manifest plus JSON, images and audio.

- Allowed file types: `json png jpg jpeg webp wav ogg mp3 ttf otf woff woff2 txt md`. A pack holding any other file
  (scripts, scenes, `.tres`, binaries…) is rejected as a whole.
- Pack files are read as raw bytes (`Image.load_from_file`, `AudioStreamWAV.load_from_file`, …).
  Nothing in a pack goes through `load()`, so a pack can never bring code in.
- Every path in a pack is relative to the pack folder and must stay inside it (no `..`).
- `packs/.gdignore` keeps the Godot editor from importing pack files; the game reads them the way it
  reads a Workshop pack.

Where packs come from (`Platform.pack_dirs()`): `res://packs/core`, then each folder in
`user://packs/`, then whatever a store backend adds (Workshop folders, later).

## `pack.json` (format 1)

| Field | Required | Meaning |
|---|---|---|
| `format` | yes | `1` |
| `id` | yes | `a-z 0-9 _`, unique across packs |
| `version` | yes | free text |
| `name` | yes | text, or `{"en": "...", "zh": "..."}` (English required) |
| `author` | no | free text |
| `forms` | yes | list of form files |
| `tear_sounds` | no | `{"marks": "<json>", "clips": ["<wav/ogg>", ...]}`; marks file maps clip file name → rising crackle start times in seconds |

## Form file

| Field | Meaning |
|---|---|
| `id` | `a-z 0-9 _`, unique in the pack. Box seeds use `"<seed>|<id>"`. |
| `name`, `title`, `code`, `price` | printed copy; `title` is 1–3 words; `price` in whole dollars |
| `colors` | `edge`, `head`, `ink` and one `tiles` colour per tier, as `#rrggbb` |
| `tiers` | 3–8 entries: `key`, `label` (text or localized), `prize`, `printed_count` (decoration only), `role`, `symbol` (square transparent image) and optional `symbol_large` (used by symbol layers with `"variant": "large"`) |
| `digit_groups` | loser digit group lengths, 2–6 each; shuffled per ticket |
| `win_display` | `whole` (one prize a ticket; it replaces the inside), `one_group` (one prize a ticket, shown in one group) or `each_group` (every group can win on its own: a ticket holds up to one prize per group, each shown in its group) |
| `layout` | a layout file in this pack (`"layouts/x.json"`) or a built-in one (`"core:single"`, `"core:windows"`, `"core:jar"`) |
| `tear_sounds` | optional, same shape as in `pack.json`; overrides the pack's rips for this form |

Tier roles drive the box generator: one or more `top` tiers with the same prize, exactly one `mid`
and exactly one `low`, every prize a whole multiple of the `low` prize.

## Layout file (format 1)

A layout decides how a ticket looks and how it opens. Packs can change everything about the look;
the paper model, timings, tear sounds rules and the deal → (band) → flip → tear → reveal flow stay
with the engine. The three built-in layouts in `core/layouts/` (`single`, `windows`, `jar`) are
complete examples (generated by `tools/make_core_layouts.py`); the other files there are the layouts
of the core forms, among them a square card (`plate`) and a 21:9 one lying (`flock`) and standing
(`kabawk`).

```json
{
  "format": 1,
  "card": { "size": [1.4, 2.0], "canvas": [420, 600] },
  "front": [ layers ],
  "interior": { "base": [ layers ], "slots": [ ... ], "digits": { ... }, "winner": [ layers ], "win_slot": [ layers ] },
  "cover_templates": { "name": { "canvas": [w, h], "layers": [ layers ] } },
  "flaps": [ { "rect": [x, y, w, h], "hinge": "left", "cover": { "canvas": [w, h], "layers": [ layers ] } } ],
  "pairs": "none",
  "band": null,
  "reveal_slide": [0.36, 0]
}
```

- `card.size`: world units, each side 0.8–2.6. `card.canvas`: design coordinates (pixels, origin top
  left) used by every layer; the game paints at twice this resolution.
- `front`: the printed face. `interior.base`: the paper under the flaps, drawn for every ticket.
- `interior.slots`: one per digit group, in order. Each has an `anchor`; `rect` is required when the
  form's `win_display` is `one_group` or `each_group`. Each ticket's (shuffled) groups fill the slots in order.
- `interior.digits`: `direction` (`row` or `column`, centred on the anchor), `pitch`, `color`, and the
  text styles `digit`, `caption` (ZERO, ONE…) and `mark` (the small digit): `font`, `size`,
  `offset` from the digit's spot, optional `max_width`.
- `interior.winner` (for `whole`): drawn instead of the slots on a winner.
  `interior.win_slot` (for `one_group` and `each_group`): drawn in a winning slot, relative to its
  `rect`. With `each_group` it is drawn once per group that won, with that group's own tier and
  prize (`{prize}`, `win_tile`, `"tier": "win"`), and `if: "verify"` holds where that group won a
  top prize.
- `flaps`: 1–12, inside the card, not overlapping. `hinge` (`left`, `right`, `top`, `bottom`) is the
  edge that stays fixed. `cover` is a cover object or the name of a `cover_templates` entry; covers
  are drawn upright on the card and stretched to the flap. List order is the order Space opens them.
  `side_pull: true` also lets a sideways swipe (along the hinge) open the flap: the tear starts at
  the free-edge corner the hand moves away from and spreads across as the hand travels.
- `pairs`: `adjacent` lets two unopened flaps with the same hinge that share a full edge tear
  together when pressed within 0.095 of that edge; `none` turns this off.
- `band`: `null`, or `{ "height": 0.05–0.6, "canvas": [w, h], "layers": [...], "breaks": [...] }`: a
  band across the middle of the card that must be broken before the card can flip. `breaks` lists
  how it can break: `slide` (drag sideways past 0.34, it slides off) and/or `split` (drag up or down
  past 0.34, it tears in the middle and the halves fall left and right); default `["slide"]`.
  Space picks one of the listed ways at random.
- `reveal_slide`: how far the card slides while opening, as shares of its width and height.

### Layers

Every layer has a `type`; any layer may add `repeat: {"count": 1–200, "step": [dx, dy]}` and
`if: "verify" | "win" | "lose"`.

| type | fields |
|---|---|
| `rect` | `rect`, `fill`, optional `radius` (rounded corners) |
| `circle` | `center`, `radius`, `fill` |
| `ellipse` | `center`, `radii`, `rotation` (radians), `fill` |
| `path` | `points`, `closed`, `fill` and/or `stroke` + `width`, `join` (`miter`/`round`), `dash` `[on, off]` |
| `text` | `text`, `pos` (baseline), `font`, `size`, `fill` and/or `stroke` + `stroke_width`, `align`, `max_width` (squeezes wider text) |
| `image` | `src` (pack image), `rect` |
| `symbol` | `tier` (index, `"win"` in winner layers, omitted inside `each_tier`), `center`, `size` (square edge), `variant: "large"` |
| `group` | `offset`, `clip` `[x, y, w, h]` (only shapes inside a clip), `layers` |
| `each_tier` | front only: `origin`, `columns`, `step`, `layers` drawn once per tier, coordinates relative to the cell; optional `tiers` (a list of tier indexes) draws cells for those tiers only, in that order, so different tiers can have different cells |

Colours: `#rrggbb`, `#rrggbbaa`, or the form's `edge`, `head`, `ink`, `tile.N`; `tile` inside
`each_tier`; `win_tile` in winner layers.
Fonts: `slab` (Alfa Slab One), `cond` (Oswald 400), `cond_bold` (Oswald 600), `lcd` (VT323),
`hand` (Patrick Hand), or a font file in the pack.
Text variables: `{title} {name} {code} {price}` everywhere; `{serial}` on the front and inside;
`{prize} {verify}` inside; `{count} {tier_prize}` in `each_tier`; `{flap_no}` on covers.
