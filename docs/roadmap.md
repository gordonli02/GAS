## 已定（G）

- **两个模式。** 自由模式保留，就是现在的 demo。剧情模式是 roguelike。
- **剧情前提。** 主角开局遭遇一件搞笑的变故（高利贷还不上、被人敲诈之类），要凑一大笔钱，
  而主角只会玩 pull-tabs。
- **三层。** 还清之后被告知利息已经利滚利，要赚更多；这样重复两三次，大体三层，
  每层限定天数。过程中买道具、升级 perk。
- **一天没有上限。** 玩家想买多少买多少，自己离场结束一天。钱够了可以提前还款，
  直接进下一层；提前还清要有奖励。还款只能一次还清。
- **第一天决策少。** 只有花不花钱，以及花在彩票上还是 perk、道具上。

  到最后一天刚好够还。纯打工线理论上没人会走，只为成就存在，优先级最低。

- **Workshop 和发售**等游戏内容都落地、能出完整游戏包之后再看。

## 一局的结构

```
一局 = 一个主角 + 一笔债
  第 1 层：起始场所，限 N 天，还清第一笔
  第 2 层：利滚利，金额更大，更高级的场景，限 N 天
  第 3 层：再来一次
每天二选一：
  进场：买票、开票、换盒，自己决定离场
  打工：拿确定的工资，这一天不能买票
然后：商店（perk、道具）→ 下一天
随时：钱够了就可以一次还清，立刻进下一层
到期还不上 = 这一局结束 → 结算，算局外的钱
```

- perk 在一局内常驻、可升级；道具是一次性消耗。
- 每层的债写在配置里，工资从债倒推（G，2026-11-07，取代 2026-11-06 的"债由打工线算出"）：
  **每一层的每一天都打工、票上一分钱不花、理财买满，到这一层的最后一天刚好还清**。工资取最小的整数美元，
  所以最后一天会多出几块钱（占位数下 $2 / $0 / $2），带进下一层。纯打工线只为成就，优先级最低：债按赌的局调，线跟着债走。
  测试和 `RunConfig.problems()` 守着它：工资少一块、少打任何一天工、理财晚一天买（第一层）、理财不买，就不够了。
  借钱也不够：**利息按天滚**（G，2026-11-06）。借的钱每天早上在欠款上滚 15%，高于理财一级的 10%，
  所以线上借钱是亏的；理财满级 30% 时借钱投理财才划算，那是钱生钱流的事。借着不还，借来的运气就一直叠。
- **理财的购买节点写在配置里**（G：第一天就买一级，后面每级准时买）：每层记一个 `savings_day`，
  占位数下是第 1 / 3 / 4 天；第一层晚于节点买就滚得少，纯打工不够。模拟器开头打印这条线：每层的债、倒推出的工资、理财在第几天买。
  占位债 $700 / $3,500 / $15,000 倒推出的工资是 $79 / $512 / $2,064。
  注意：后两层理财二级、三级在层内是亏的（第二层不买二级、第三层晚一天买三级反而多），只有第一层的节点是硬的。
- 工资在一层里是一个数，由这一层的债倒推。后两层的债要等"利滚利"时才知道。
  理财要花钱买，买不买本身是决策；原来"涨薪曲线不告诉玩家"的设计不要了。
- **要改（G，2026-11-10，见"数值方向"九.3）**：工资压到一天只占债的 3–5%，纯打工线主要靠理财的复利凑满（理财要变强）；
  纯打工线不付层中检查点。每层的天数也要统一（九.2：G，2026-11-13，每层 5 天），上面的 `savings_day` 和第三层原来的 7 天跟着改。

## 数值方向（G，2026-11-10）

调数值之前先定的方向和最终目标，之后的量数和调数都对着这一节验收。它取代了下面"通关率目标"里机器人的目标和排序、
"已定"里"盲买不赚不赔"和读盒的内容，以及几处被点名的旧规则（各处标了）。落到 **M9.8**（排在 M10 前，先后见那一节，G，2026-11-13）；
所有的量数都要先做第七节（机器人）。

### 一、通关率和排序

1. 赢主要靠 perk 构筑；盲买必亏（回报 0.78）。
2. 不构筑就基本过不了：gamble、borrow、blind、skip 都在 5% 以下。borrow 只是"借满了赌、不买 perk"，因为有利息，应该 ≤ gamble；
   真正的借钱流是专精里的 money。
3. 排序：各专精流派（clearing、jackpot、small、batch、money）> build（只抓通用好牌）> perks（乱买）> 不构筑的那四个。
4. 各专精流派的机器人都在 25% 左右（大约 20–30%），small 也一样。整体高低靠债调，流派之间拉平靠 perk 调。
   build 和 perks 的目标等第一次量完再定。
5. 五条流派都是主流派，都要能独立通关。
6. 所有目标都按首档难度、没有局外加成来量。

### 二、流派之间的互动

1. 混搭的上限比纯流派高，但更难凑齐。
2. 爆发靠"转换"（把一条流派的计数算作另一条的），不靠叠乘；转换的 perk 要有代价或前置。
3. 桥 perk：做一些，界面上不标，也不提示它连着哪两条流派，让玩家自己发现；发牌时偏向玩家已有的流派，也不说。
   前提是所有卡片的关键词统一。
4. 互斥用软的（都能拿，但互相抵消）。三个方向：抢同一种资源、条件相反、节奏冲突。"用隐藏的桥化解冲突"先不做。

### 三、读盒

目标：**玩家再也不能 100% 拿到某一盒的精确信息。只告诉已经发生的事，不告诉盒里剩下什么。**

1. ①：奖单只显示大奖有没有被取走，别的不写。
2. ②（流水：这盒已经卖了多少张、开出了多少钱）：先用模拟器量"过去吐的钱"和"剩下的回报"之间的关系，再决定留不留。
3. ③（草案）：剩余张数的约数（按 50 取整）。
4. 删掉：原来的④（精确的数）、⑤里"记事本记每一盒"、冷热（HOT / COLD）。
5. 界面上任何地方都不出现一盒的奖数总表（开发面板不算）。
6. BOX REPORT 改成"看这一盒被别人卖掉的那部分里开出了什么"。
7. PEEK / INFORMANT、钓上来都保留。PEEK / INFORMANT 看的是还没开的票，是**有意留的例外**（花钱买、只看局部），不是漏洞，别当成违反本节目标删掉。
8. 加注原来"和读盒联动"的理由不成立了，要重新找它成立的依据。
9. 账本里加一个统计菜单（每种票开了多少、中奖率等），不影响游戏。

### 四、别的客人和占列

1. 盒子上机时已经被别的客人卖掉一部分。
2. 客人买票按玩家的动作推进（比如玩家每买 N 张推进一次），不按真实时间；场景可以有不同的客流。
3. "被卖掉多少"要是一个两头都有好处的取舍，不能有一头绝对占优。
4. 占列：客人不买玩家上一次买票的那一列。这是基础规则。
5. 别的控制方式往后放：早场 / 晚场放到第二层以后，或者只通过兼职出现；perk 和道具作为流派的材料；请酒保留列等 M12。

### 五、last sale

按玩家自己在这一盒里花的钱算（某个比例），不再是固定的数。原因：盒子会被别人卖掉一部分以后，固定的 last sale 不用 perk 就稳赚。

### 六、票种特性

设计清单，每张票的特性都要过一遍：

1. 触发条件用流派的关键词；
2. 至少有一条流派能喂它，一条流派能吃它；
3. 两个把手：一个减负面，一个加正面；
4. 不透露未来的信息；
5. 不能让某一种票绝对占优；
6. 账要平，同时要有玩家能感觉到的坏处，不能是纯收益。

具体的票：

- **Lucky Spur**："封条印冷热"推翻。方向是"连中两张，第二张 +50%"，挂钩连庄、多中、MIDDLE CUT。
  **代价（G，2026-11-13）**：落单的中奖（前一张没中）−25%。减负面的把手是"落单不扣"；基础奖表跟着一起算，盲买回到 0.78。
- **Big Catch（G，2026-11-13）**：顶奖出了之后，这一盒的 last sale ×2；**顶奖没出就清盒，last sale 减半**（原版只有好处，违反第 6 条）。
  把手照旧：鱼群（不要求顶奖出过）、收尾人（×2 变 ×4）。
- **Hot Plate（G，2026-11-13）**：不变。连中一张热一级，每级下一张 +X%，输一张就凉；把手照旧：保温、红热。
  和 Lucky Spur 都吃连中：Hot Plate 是长连，Lucky Spur 是成对。
- **Pecking Order（G，2026-11-13）**："按顺序出"推翻（能数，透露未来，违反第 4 条），改成**啄序**：
  这张中奖比这一盒上一张中奖大，+50%；比它小，−25%。把手：减负面"小了不扣"，加正面"+50% 变 +100%"。
- Ka-Bawk!、One Flock、Nugget Rush 等做到 M9.8 第 7 步再挑（草案：Ka-Bawk! 中奖翻倍、没中的票再扣一张票钱；
  One Flock 单张买的中奖 −20%；Nugget Rush 离场时没换掉的金块作废）。
- **Peckeye**："看下一张中不中"推翻，改成菠菜升档：
  - 没中的票里有菠菜罐，攒满 3 罐，下一张票中了就升一档，没中这 3 罐就白费。
  - 坏处：中奖更少；罐子在换列、换盒、离场时清零；多数时候会白费。
  - 两个把手：减负面是"作用在下一个中奖"，加正面是"升两档"。
  - 基础奖表配合菠菜一起算，盲买回到 0.78。

### 七、测试机器人

1. 分三层：数据层（`box_return` 这类，算理想回报、天花板、失控的组合）、策略层（流派机器人跑整局，验收通关率）、
   对抗层（找漏洞的机器人、组合搜索）。
2. 模块化：一天拆成几块（进场还是打工、选列、买多少和什么时候走、买 perk、用道具、换盒），每条流派只换跟它有关的那几块，
   其他用一套合理的默认做法。
3. 先验证机器人会玩这条流派：记核心 perk 的触发次数；触发得少就是机器人坏了，不是流派弱。
4. 一条流派的强度，取 3–5 个参数变体里最好的那个。
5. 报死因：第几层第几天、死时的钱、持有的 perk、打工天数、买了多少张票。
6. 省时间、减噪声：公共随机数（同一批种子）；先跑 100 局，明显偏离的不再跑满；可以从第二层开始时的典型状态直接开局。
7. 对抗层：perk 组合的自动搜索；每个新规则配一个找漏洞的机器人（下一批：被卖掉一部分 × last sale、占列）。
8. 混搭：每张桥配一个两条流派的机器人，验证混搭 ≥ 纯流派；再加一个随机乱混的机器人，验证它比纯流派差。

### 八、增长和债务曲线

1. 爆发可以从第二层中后期开始。
2. 超出债务的钱换成局外金钱时递减（比如对数）。
3. **债务用固定的曲线**（参考 Balatro），写死在配置里，不按玩家的数据实时调整。三层是一张表（调数的杠杆），无尽模式用公式接上去。
   **"更陡"按票价单位算**：现在的债合票是 700 / 700 / 750 张（合盒 3.5 / 2.3 / 1.5），×5 / ×4.3 的债正好被 ×5 / ×4 的票价抵掉，
   按盒算后面反而更松。债的倍率要高过票价的倍率，多出来的那部分才是难度增长，对着 perk 带来的回报增长定。票价单独是一根杠杆。
4. **钱全部带进下一层，先不加防滚雪球的规则，用量数决定。** 模拟器记"进下一层时带的钱 ÷ 下一层的债"；
   强局里这个比值经常 ≥ 1（一进层就能还清）的话，再加结转上限：带进下一层的现金最多是下一层债的某个比例，
   超出的部分转成局外金钱（按第 2 条递减）或者一次奖励三选一，上限按量出来的分布定。
5. **"债主按你的现金加下一层的债"不进主线**，放进难度档当惩罚之一（M13.5 的第 3 档；还清时抽现金的 X%，和十一.5 的滞纳金、抵押同一类）。
   不进主线的原因：它罚的正是爆发和多赚，和第 2 条的递减叠成两次税；还款前花光、转进理财或余额就能躲，"手里的钱"算哪些每条都是漏洞；
   它的比例和曲线互相抵消，靶子难对。放在难度档里，这些坏处正是想要的效果。
6. **曲线不在界面上提前显示**：第一局里下一层的债要到债主的台词里才说出来（"已定"里的"还清之后被告知利滚利"），
   之后每局都一样，老玩家心里有数。剧情的惊喜留给第一局，可规划性留给第二局以后。
7. 3 层以后加一个无尽模式（债务超指数增长），给爆发一个去处。

### 九、层、天、打工

1. 难度曲线参考杀戮尖塔 2：每层的条件通关率接近，难度集中在每层期末的还款。
2. 每层的天数统一：**每层 5 天**（G，2026-11-13），一局正好 21 次三选一。
3. 打工：理想是每层 0 天；第一层可以多打 1–2 天换容错；第三层最好不打工。
   - 做法：理财承担纯打工线的大部分，工资压低，让一天工资只占债的 3–5%，纯打工线靠理财的复利凑满。
   - **纯打工线不付层中检查点**（G，2026-11-10），钱一直留在理财里滚；线上"刚好还清"按不付检查点来算。
   - 跟着要量：理财变强以后对所有玩家的影响。
4. "天"的意义：
   - 一天的资源有限：机器每天只补一次货，同一天里换盒越换越贵；
   - 一天就是一轮（早上发牌 → 进场或打工 → 结束），在界面和文案上讲清楚。

### 十、发牌和货架

1. 漏洞：现在一轮三张可以买好几张，再付钱刷新又来三张，一天能一直循环到全买完。要堵上。
2. 真正的三选一：一轮只拿一张，拿了这一轮就结束；也可以放弃这一轮换一个道具（现有的规则）。
3. 刷新只能在拿之前，价格照旧翻倍。
4. 只在早上：去掉"待会儿"，早上的卡片必须当场处理；关掉就没了，手机上也不能再买。
5. 货架不能刷新，每天早上自动换一批货；全天都能买。
6. 发牌只发新 perk；升级移到货架，花钱买，像 Hades 的商人卖石榴、Monster Train 的升级石。
7. 额外的三选一：层中检查点付清给一次；每层还清给一次；提前还清每提前一天补一次，在这之上还可以再加奖励。
   这些奖励性质的三选一，可以选"一张高稀有度的新 perk"或者"免费升级"。
8. 跟着要量：一局大约 21 次三选一，每条流派到第几层能凑齐核心。

### 十一、层中检查点

1. 每层中间，债主要你先付一笔（比如这一层债的 25–30%，待定）。
2. 付了：算预付，计入这一层的还款，另外给奖励（见第十节第 7 条）。
3. 不付：首档难度下什么都不发生，到期照常还全额。这是一个纯粹的机会成本决策：钱提前离开本金，这几天不能拿去赌、去滚理财。
4. 哪天付都行（不一定在检查点那天），也可以用 LOAN 借钱来付。
5. 惩罚放进难度档（M13.5 的第 1 档）：高档难度下不付要选滞纳金（没付的部分 ×1.5 加到期末的债上）或者抵押
   （债主拿走一个道具，或者某个 perk 降一级，玩家自己挑）。
6. 债主的服务"这次先不收"：花钱买，不能有免费的版本。在有惩罚的难度档里，它是绕开惩罚的一条路。

### 十二、要量的

5. 检查点收多少、奖励多大，才是一个真决策。
6. 进下一层时带的钱 ÷ 下一层的债（第八节第 4 条，决定要不要结转上限）。

## 通关率目标（G 定数，2026-11-06）

数值那一步的靶子。先分清三件事：

- **纯打工线不进这个排序。** 它是围绕成就设计的一条确定的 route（"只打工不赌博通关"），不是一种玩法；
  通关率都指赌了的局。
- **人和机器人分开定。** 人会读盒、会看时机、会在该走的时候走；机器人不会。机器人的数只是数值那一步的验收条件。
- **按层看条件概率**：到了这一层的人里有多少能过这一层。整体是三个相乘。

### 人（基础难度）

| 层 | 过这一层的概率 | 熟练 / 搭起来之后 | 这一层是什么 |
|---|---|---|---|
| 第一层 | 60% 左右，不超过 70% | 80% | 学会：5 天，决策只有买不买、买票还是 perk。它是筛子，像杀戮尖塔的第一幕 |
| 第二层 | 60% 到 70%，可以比第一层略高 | 80%（第一层 perk 搭得好，或有局外道具的加成） | 成形：倍率 ×5，流派凑起来，读盒该到手 |
| 第三层 | 50%，要显著低（G，2026-11-13：维持） | 50% | 收网：倍率 ×20，~~7 天~~ 5 天，build 不成就过不了 |

- **首局，无局外道具**：10%。第一局过不了是正常的。
- **失败落在哪一层**（基础数下）：第一层 35%、第二层 23%、第三层 21%，剩下 21% 通关。

### M8 一局的骨架（已完成，等 G 测）

做的时候定下来的几处（可以改；代码里的落法见 `docs/decisions.md` 的 M8 一节）：

  到了第三层还拿第一层的工资，一班只够买六张票，打工就起不到兜底的作用。

3. **打工**：占掉一整天，当天机器不卖票。工资来自一条涨薪曲线（数据），

5. **关卡数据**：每个场景的票价、盒大小范围、奖表、换盒费、LOAN 基础额度；

### M13.5 难度档（G，2026-11-10：整个游戏做完之前不加）

**什么时候做**：M13 的内容（主角、场景、局外进度、票种）全部落地、首档的数值调完之后才加。在那之前：
- 所有的目标、量数和调数都只按首档（"数值方向"一.6）；
- 写代码时不为难度档预留钩子。要调的数本来就在 `RunConfig` 里，到时候每一档就是在首档配置上加一份覆盖；
  只有加新规则的档（比如检查点的惩罚）才需要新代码，做到哪档写到哪档。

**参照**：Balatro 的赌注（每档加一条规则，层层叠加，多数是规则而不是纯数值）、杀戮尖塔的进阶、Hades 的热度（自选的规则修改）。
我们取 Balatro 的做法：一条线往上爬，不做 Hades 式的自由组合（组合太多，没法逐档验收）。

**原则：**
1. **一档只加一样东西，层层叠加。** 第 N 档包含前面所有档的规则。玩家要能一句话说出这一档多了什么。
2. **规则优先，纯数值最多两三档。** 规则会逼玩家换打法（"检查点必须付了"），纯数值只是让一切都更难。
3. **不能让某一条流派在高档直接死掉。** 每加一档，五条专精流派的机器人各跑一次；最高档里每一条都要还能通关，各条之间的差距
   不比首档大太多。哪一档专门克一条流派，就要换一条规则。
4. **不碰核心的感觉。** 读盒已经只说已经发生的事（"数值方向"第三节），难度档不再往下砍信息；盲买亏多少也不靠难度档调
   （盲买本来就该输，压它只会让所有人一起变难）。
5. **纯打工线只在首档保证**："只打工不赌博通关"的成就只在首档算；高档的规则可以打破这条线，不用为它调数。
6. **解锁**：过了第 N 档才能选第 N+1 档，按主角分开记（主角在 M10 定，到时再确认）。档越高，结算的局外金钱越多（倍率占位）。
7. **通关率的靶子**："通关率目标"里的基础数是首档；最高档整体 10% 以下（人）。中间各档大致等比往下走，
   机器人按人的三分之二验收，每档的机器人目标到做的时候再定。

**各档草案**（规则都是现有系统里已经定下的惩罚，顺序和数都是占位；先加"多一个决策"的，再加"资源变紧"的）：

| 档 | 加的规则 | 逼玩家做什么 | 出处 |
|---|---|---|---|
| 0 | 首档：现在的游戏 | | |
| 1 | **检查点有惩罚**：不付要选滞纳金（没付的部分 ×1.5 加到期末的债上）或者抵押（债主拿走一个道具，或者某个 perk 降一级，玩家自己挑）。债主的服务"这次先不收"是花钱绕开的路 | 检查点从"可付可不付"变成要提前算好本金 | "数值方向"十一.5、十一.6 |
| 2 | **客流更大**：盒子上机时被别的客人卖掉的部分更多，客人推进得更快 | 抢盒、占列更要紧，清盒和 last sale 更难拿 | 第四节 |
| 3 | **利滚利看现金**：还清时手里现金的 X% 加到下一层的债上 | 还款前把钱换成 perk 和道具，别攒着；爆发的钱一部分被债主抽走 | 八.5 |
