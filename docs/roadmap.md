# Roadmap（demo 之后）

草案，2026-11-06。只排功能和游戏系统，数值和微调留到各自的里程碑。
"G" 是项目负责人。游戏名 Last Sale 是暂定名，G 提出之前不动。

## 已定（G）

- **两个模式。** 自由模式保留，就是现在的 demo。剧情模式是 roguelike。
- **剧情前提。** 主角开局遭遇一件搞笑的变故（高利贷还不上、被人敲诈之类），要凑一大笔钱，
  而主角只会玩 pull-tabs。
- **三层。** 还清之后被告知利息已经利滚利，要赚更多；这样重复两三次，大体三层，
  每层限定天数。过程中买道具、升级 perk。
- **一天没有上限。** 玩家想买多少买多少，自己离场结束一天。钱够了可以提前还款，
  直接进下一层；提前还清要有奖励。还款只能一次还清。
- **第一天决策少。** 只有花不花钱，以及花在彩票上还是 perk、道具上。
- **perk 是成长的来源。** 盲买的期望大约不赚不赔；玩家从第一天起就能买 perk 或攒钱买 perk，
  收益期望和中奖金额随 perk 逐渐变大。
- **打工占掉一整天。** 选了打工，这一天就不能买彩票，但可以买 perk 和道具。收益确定。
- **纯靠打工刚好能通关。** 三层里每一天都打工、没有任何额外消费，工资加起来刚好付完债。
  工资按一条不告诉玩家的涨薪曲线走：打工到固定的某几天涨薪。工资如果一直不变，
  玩家一开始就能算出一直打工就能通关。
- **成就系统**放在 roadmap 靠后的位置。"只打工不赌博通关"是其中一个成就。
- **LOAN 借的钱要还**：连同利息计入这一层的应还总额。
- **剧情模式也有 LOAN。** 开始只有一个基础额度；基础额度每层上升，perk 也能提高额度。
- **读盒是 perk，而且不靠前。** 奖表的真实数量、剩余票数、记事本按盒记录已开和已中，
  都是读盒 perk 的内容，分几个级别。最低级别只给基础数据。
  低级别不能把游戏变成纯算牌，要保住"真的在赌、在开彩票"的感觉。
- **换新盒要付费。**
- **Last sale 奖。** 买走盒里最后一张票有额外奖。
- **场景按层走。** 现有三个场景（Diner、Bar、Bingo Hall）是三个主角各自的起始场所，
  后面的层换到更高级的场景（豪华赌场、豪华游艇）。
  用局外的钱可以买场景（例如在豪车后座玩 pull-tabs，这是高级场景），
  买了之后可以用它替换某一层的场景。
- **两种钱。** 局内的钱：还债、买票、买道具、升级 perk。局外的钱：每局结算时算出来，
  用来升级人物、买跨局可用的道具和场景。
- **NPC 先定类型，再设计具体 NPC。** 类型：叙事型、功能型、两者兼具。
- **世界观里的角色都是鸡。** 只换人物形象，其他元素不变。
  （票面上本来就印着 PAYABLE IN EGG MONEY。）
- **主角的起始 perk** 等做 perk tree 或角色时再定。
- **Playtest 放在 M10 之后**，用一个主角加第一层先测核心循环。
- **Workshop 和发售**等游戏内容都落地、能出完整游戏包之后再看。

## 一局的结构

```
一局 = 一个主角 + 一笔债
  第 1 层：起始场所，限 N 天，还清第一笔
  第 2 层：利滚利，金额更大，更高级的场景，限 N 天
  第 3 层：再来一次
每天二选一：
  进场：买票、开票、换盒，自己决定离场
  打工：拿确定的工资，这一天不能买票
然后：商店（perk、道具）→ 下一天
随时：钱够了就可以一次还清，立刻进下一层
到期还不上 = 这一局结束 → 结算，算局外的钱
```

- perk 在一局内常驻、可升级；道具是一次性消耗。
- 涨薪曲线和每层的债是一起定的：**每一层的每一天都打工、一分钱不花，
  到这一层的最后一天刚好还清，不多不少**。模拟器里有一条测试守着它。
  少打一天工、买过一张票或一个 perk、借过一次钱，纯打工就不够了。
- 涨薪是按"这一层里打工的第几天"发生的固定事件，玩家事先看不到曲线，只在涨的那天知道。
  后两层的债也要等"利滚利"时才知道，所以开局算不出这条路走得通。

## 里程碑

每个系统先在 `src/core` 写成纯逻辑并配测试，再做界面。每个里程碑结束时停下来，告诉 G 测什么。

### M8 一局的骨架（已完成，等 G 测）

做的时候定下来的几处（可以改；代码里的落法见 `docs/decisions.md` 的 M8 一节）：
- M8 还没有 perk，LOAN 只做基础额度和每层上升；额度留一个钩子给 M9 的 perk。
- **涨薪按"这一层里打工的第几天"算**，不按整局算。按整局算的话，第一层一直在开票的玩家
  到了第三层还拿第一层的工资，一班只够买六张票，打工就起不到兜底的作用。
- 起始现金算进纯打工那条线里（第一层的债 = 工资总和 + 起始现金），这样"刚好"是严格的。
- **关卡的数值跟着层走，场景只管样子。** 以后局外买的场景可以替换某一层的场景，
  所以票价、债、工资、额度都记在层上。现在三层依次是玩家选的桌子和另外两个房间。
- **每层有一个倍率**：票价、奖金、钞票面额都乘它（现在是 1、5、20）。
- 离场要二次确认（G，M8 测后）：离场卡片写明有多少张没开的票会被丢掉，确认后才丢。
  所以不会有票跨天或跨层。
- 还款由玩家自己按（G）：默认把这一层的每一天玩完；只有最后一天结束时钱够才自动还。
- 所有数值都是占位，等数值那一步再调。现在的占位数值：三层的债 $1,000 / $5,000 / $20,000，
  期限 5 / 6 / 7 天，借款利息 25%，换盒费 $25 起，last sale 奖 $50 起。
- 提前还清的奖励先记成"剩余天数"，结算时折成局外的钱（M13 定公式）。
- 商店在 M9 才有；M8 的"打工那天还能买 perk"先只留流程上的位置。

任务，按顺序：
1. **局的状态**（`src/core/run_state.gd`）：层、天、债、期限；开局、过一天、一次还清、
   进下一层并利滚利、到期失败、第三层还清通关。纯逻辑加测试。
   同时记下这一局的统计（买票数、打工天数、借款、消费），结算和以后的成就都用它。
2. **局内账本**：`Economy` 的起始现金来自局的配置；账本多出工资、还款、换盒费、商店支出；
   恒等式跟着扩展。自由模式的规则和测试不动。
3. **打工**：占掉一整天，当天机器不卖票。工资来自一条涨薪曲线（数据），
   在固定的打工天数涨薪；界面只显示今天的工资，不显示曲线。
4. **LOAN**：基础额度按层上升，额度可被外部加成；借款和利息计入应还总额。
5. **关卡数据**：每个场景的票价、盒大小范围、奖表、换盒费、LOAN 基础额度；
   每层的债和天数。
   盒生成器从它取参数；自由模式仍然和 web 版逐位一致（golden 测试不动）。
   每层用哪个场景是一张可替换的表（为局外买的场景留位置）。
6. **换盒付费**：`MachineLogic` 换掉某一列的盒子，扣费，重新上货。
7. **Last sale 奖**：盒里最后一张票卖出时给额外奖，机器 LCD 提示。
8. **无头模拟器**（`tools/sim_runs`）：几种机器人（盲买、只打工、混合、借满）各跑大量的局，
   输出通关率和用掉的天数；断言只打工的机器人每层都在最后一天刚好还清、通关时余额为零，
   而少打一天工或花过一分钱就过不了。
9. **存档**：存档版本加一；剧情模式的局和自由模式分开存；局的种子。
10. **流程和界面**：菜单里选模式（自由、新的一局、继续）；每天开始时选进场还是打工；
    机器旁的债务、期限和 LOAN 读数；离场后的当日小结；开局变故和每次"利滚利"的剧情卡
    （先用文字，中英文）；一局结束的结算画面。
11. **驱动工具**：`tools/drive_run` 用合成输入打完一局，像 `drive_game` 那样逐帧查账。

**G 测：** 不带任何 perk 完整打一局：进场、打工、借钱、换盒、清盒尾拿 last sale、提前还款、到期失败。

### M9 技能与道具
- 效果钩子系统（纯逻辑），perk 和道具都是数据。
- perk tree。第一批 perk 是经济和运气方向的：提高收益期望、中奖金额、LOAN 额度等。
- 读盒是一条分级的 perk 线，靠后、要花钱才走得到。低级别给粗略的、定性的信息，
  高级别才给准确数字和记事本。
- 道具：信息类、经济类、操作类。
- 商店（进场或打工之后都能逛）；perk 升级。
- **G 测：** 第一天只有"买票还是买 perk"；perk 多了之后期望和奖金变大；
  读盒到手后，买哪一列、何时换盒、要不要清盒尾变成决策。
