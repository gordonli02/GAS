# Roadmap（demo 之后）

草案，2026-11-06。只排功能和游戏系统，数值和微调留到各自的里程碑。
"G" 是项目负责人。游戏名 Last Sale 是暂定名，G 提出之前不动。

## 已定（G）

- **两个模式。** 自由模式保留，就是现在的 demo。剧情模式是 roguelike。
- **剧情前提。** 主角开局遭遇一件搞笑的变故（高利贷还不上、被人敲诈之类），要凑一大笔钱，
  而主角只会玩 pull-tabs。
- **三层。** 还清之后被告知利息已经利滚利，要赚更多；这样重复两三次，大体三层，
  每层限定天数。过程中买道具、升级 perk。
- **一天没有上限。** 玩家想买多少买多少，自己离场结束一天。钱够了可以提前还款，
  直接进下一层；提前还清要有奖励。还款只能一次还清。
- **第一天决策少。** 只有花不花钱，以及花在彩票上还是 perk、道具上。
- **perk 是成长的来源。** 盲买的期望大约不赚不赔；玩家从第一天起就能买 perk 或攒钱买 perk，
  收益期望和中奖金额随 perk 逐渐变大。
- **打工占掉一整天。** 选了打工，这一天就不能买彩票，但可以买 perk 和道具。收益确定。
- **纯靠打工刚好能通关。** 三层里每一天都打工、没有任何额外消费，工资加起来刚好付完债。
  ~~工资按一条不告诉玩家的涨薪曲线走：打工到固定的某几天涨薪。工资如果一直不变，
  玩家一开始就能算出一直打工就能通关。~~
  **改了（G，2026-11-06）**：去掉涨薪曲线，工资在一层里不变（层与层之间跟倍率走）。
  "只打工能通关"改成**"只打工 + 理财买满能通关"**：理财是货架上的 perk，每天早上让现金长一点，
  打工日也算；一分钱不花在票上、理财买满、每天打工，到每层最后一天刚好还清。
  这样第一天就多了一条确定的路（买理财），"买票还是 perk"里 perk 这边有了不赌的选项。
  细节见 `docs/perk_research.md` 第五节第 9 条。
- **成就系统**放在 roadmap 靠后的位置。"只打工不赌博通关"是其中一个成就。
- **LOAN 借的钱要还**：连同利息计入这一层的应还总额。利息按天滚（G，2026-11-06）。
- **剧情模式也有 LOAN。** 开始只有一个基础额度；基础额度每层上升，perk 也能提高额度。
- **读盒是 perk，而且不靠前。** 奖表的真实数量、剩余票数、记事本按盒记录已开和已中，
  都是读盒 perk 的内容，分几个级别。最低级别只给基础数据。
  低级别不能把游戏变成纯算牌，要保住"真的在赌、在开彩票"的感觉。
- **换新盒要付费。**
- **Last sale 奖。** 买走盒里最后一张票有额外奖。
- **场景按层走。** 现有三个场景（Diner、Bar、Bingo Hall）是三个主角各自的起始场所，
  后面的层换到更高级的场景（豪华赌场、豪华游艇）。
  用局外的钱可以买场景（例如在豪车后座玩 pull-tabs，这是高级场景），
  买了之后可以用它替换某一层的场景。
- **两种钱。** 局内的钱：还债、买票、买道具、升级 perk。局外的钱：每局结算时算出来，
  用来升级人物、买跨局可用的道具和场景。
- **NPC 先定类型，再设计具体 NPC。** 类型：叙事型、功能型、两者兼具。
- **世界观里的角色都是鸡。** 只换人物形象，其他元素不变。
  （票面上本来就印着 PAYABLE IN EGG MONEY。）
- **主角的起始 perk** 等做 perk tree 或角色时再定。
- **Playtest 放在 M10 之后**，用一个主角加第一层先测核心循环。
- **Workshop 和发售**等游戏内容都落地、能出完整游戏包之后再看。

## 一局的结构

```
一局 = 一个主角 + 一笔债
  第 1 层：起始场所，限 N 天，还清第一笔
  第 2 层：利滚利，金额更大，更高级的场景，限 N 天
  第 3 层：再来一次
每天二选一：
  进场：买票、开票、换盒，自己决定离场
  打工：拿确定的工资，这一天不能买票
然后：商店（perk、道具）→ 下一天
随时：钱够了就可以一次还清，立刻进下一层
到期还不上 = 这一局结束 → 结算，算局外的钱
```

- perk 在一局内常驻、可升级；道具是一次性消耗。
- 工资、理财和每层的债是一起定的（G，2026-11-06，取代原来的涨薪曲线）：
  **每一层的每一天都打工、票上一分钱不花、理财买满，到这一层的最后一天刚好还清，不多不少**。
  模拟器里有一条测试守着它。少打一天工、买过一张票、理财没买满，就不够了。
  借钱也不够：**利息按天滚**（G，2026-11-06）。借的钱每天早上在欠款上滚 15%，高于理财一级的 10%，
  所以线上借钱是亏的；理财满级 30% 时借钱投理财才划算，那是钱生钱流的事。借着不还，借来的运气就一直叠。
- **理财的购买节点写在配置里**（G：第一天就买一级，后面每级准时买）：每层记一个 `savings_day`，
  占位数下是第 1 / 2 / 4 天；晚于节点买就滚得少，纯打工不够。模拟器开头打印这条线。
- 工资在一层里是一个数，层与层之间跟倍率走。后两层的债要等"利滚利"时才知道。
  理财要花钱买，买不买本身是决策；原来"涨薪曲线不告诉玩家"的设计不要了。

## 通关率目标（G 定数，2026-11-06）

数值那一步的靶子。先分清三件事：

- **纯打工线不进这个排序。** 它是围绕成就设计的一条确定的 route（"只打工不赌博通关"），不是一种玩法；
  通关率都指赌了的局。
- **人和机器人分开定。** 人会读盒、会看时机、会在该走的时候走；机器人不会。机器人的数只是数值那一步的验收条件。
- **按层看条件概率**：到了这一层的人里有多少能过这一层。整体是三个相乘。

### 人（基础难度）

| 层 | 过这一层的概率 | 熟练 / 搭起来之后 | 这一层是什么 |
|---|---|---|---|
| 第一层 | 60% 左右，不超过 70% | 80% | 学会：5 天，决策只有买不买、买票还是 perk。它是筛子，像杀戮尖塔的第一幕 |
| 第二层 | 60% 到 70%，可以比第一层略高 | 80%（第一层 perk 搭得好，或有局外道具的加成） | 成形：倍率 ×5，流派凑起来，读盒该到手 |
| 第三层 | 50%，要显著低 | 50% | 收网：倍率 ×20，7 天，build 不成就过不了 |

- **整体约 30%**：这是搭起来之后的数（0.8 × 0.8 × 0.5 ≈ 32%）。没搭起来的局约 20%（0.65 × 0.65 × 0.5）。
  要注意第三层定在 50% 之后，整体 30% 等于前两层都要到 78% 左右；前两层 65% 的话整体就是 20%。
- **首局，无局外道具**：10%。第一局过不了是正常的。
- **失败落在哪一层**（基础数下）：第一层 35%、第二层 23%、第三层 21%，剩下 21% 通关。
  按失败的局算，第一层占 44%。第一层是筛子，这是定了 60% 的必然结果；搭起来之后筛子就松了（80%），失败往第三层移。
- **提前还款**：每层通关的人里，第一层 30%、第二层 20%、第三层 10% 是提前还的。
- **天文数字**：每局最大单奖的中位数是"几十倍票价"，第 99 百分位才是上万倍。
- 这些是基础难度。之后的难度档（Balatro 的赌注、Hades 的热度）往下压，最高档整体 10% 以下。

**别家的曲线，做参照**（每局胜率和"玩家里多少人赢过"是两个数，别混）：
- 杀戮尖塔一代 A0 每局胜率社区统计约 9%，A20 约 3%；二代 A0 约 16%，整体约 25%（2.4 亿局）。
  按玩家算，老数据里"用静默通关"的玩家占 50%。
- Hades 按玩家算：83% 的人过过第一层（Tartarus），44% 的人至少逃出去过一次。首次逃出常在第十到二十局。
- Balatro 按玩家算：72% 的人赢过一局；红赌注 44%，黑赌注 30%。基础难度好过，赌注往上压。
- 我们的"成形后 30%"在这一类里偏宽松，和 Balatro 一路：有确定的兜底、有局外道具的游戏，基础难度就该这样；
  难度档负责往下压。

### 机器人（模拟器，数值那一步的验收条件）

机器人不会读盒、不会挑时机走，所以目标比人的基础数再低一截（约三分之二）。
work 不在表里（规则上 100%）。

| 机器人 | 目标 | 现在（占位数，300 局：整体 / 每层条件） | 为什么是这个数 |
|---|---|---|---|
| build（买流派 perk 再赌） | 25%（20 到 30） | 1.0%（45 / 10 / 23） | **主靶子**：perk 让赌赢，机器人也该看得出来。每层约 65 / 65 / 60 |
| gamble（**赌为主，偶尔打工**：本金不够一天的票才打工） | 15% | 12.0%（47 / 52 / 49） | 不构筑只靠赌的稳健玩家 |
| perks（见便宜就买） | 10% | 2.7%（51 / 16 / 33） | 乱买 perk 比不买好一点，比有流派差得多 |
| borrow（借满了赌） | 8% 以下 | 5.0%（53 / 25 / 39） | 借钱是工具，不是出路 |
| blind（盲买） | 5% 以下 | 0.7%（50 / 12 / 11） | 不想就赌，大多数该输 |
| skip（从不买 perk） | 5% 以下 | 0.7%（48 / 10 / 13） | 没有 perk 就是在和期望 1.0 的机器对赌 |

- 排序必须是 build > gamble > perks > borrow ≥ blind ≈ skip。build 低于 gamble 就说明 perk 不值钱；
  blind 高于 5% 说明盒子太肥。
- 原来的 mixed（打工为主偶尔赌）换成 gamble（赌为主偶尔打工）；模拟器里改了（M9.5 第 5 步）。
- 每美元回报：blind 约 1.0；build 到第三层后半 1.5 到 2.0；"20 张就换盒"机器人不超过 1.0。
- 现在的差距在第一层：build 机器人把钱花在 perk 上就没本金，第一层就死。
  数值那一步先动的是第一层的债和 perk 价格，不是奖表。

### 怎么量

- 模拟器每种机器人 300 局，打印每层条件通关率和整体，和这张表并排。
- Playtest（M11）量人的：每局记到哪一层、哪天死的、提前还没有、最大单奖、有没有局外道具。

### M8 一局的骨架（已完成，等 G 测）

做的时候定下来的几处（可以改；代码里的落法见 `docs/decisions.md` 的 M8 一节）：
- M8 还没有 perk，LOAN 只做基础额度和每层上升；额度留一个钩子给 M9 的 perk。
- **涨薪按"这一层里打工的第几天"算**，不按整局算。按整局算的话，第一层一直在开票的玩家
  到了第三层还拿第一层的工资，一班只够买六张票，打工就起不到兜底的作用。
- 起始现金算进纯打工那条线里（第一层的债 = 工资总和 + 起始现金），这样"刚好"是严格的。
- **关卡的数值跟着层走，场景只管样子。** 以后局外买的场景可以替换某一层的场景，
  所以票价、债、工资、额度都记在层上。现在三层依次是玩家选的桌子和另外两个房间。
- **每层有一个倍率**：票价、奖金、钞票面额都乘它（现在是 1、5、20）。
- 离场要二次确认（G，M8 测后）：离场卡片写明有多少张没开的票会被丢掉，确认后才丢。
  所以不会有票跨天或跨层。**M9 之后改了（G）**：同一层里没开的票留到第二天，只有这一层结束时才丢，见 M9 一节。
- 还款由玩家自己按（G）：默认把这一层的每一天玩完；只有最后一天结束时钱够才自动还。
- 所有数值都是占位，等数值那一步再调。现在的占位数值：~~三层的债 $1,000 / $5,000 / $20,000~~
  （M9.5 起债由打工加理财的线算出：$1,136 / $5,250 / $21,883，工资 $150 / $700 / $2,500），
  期限 5 / 6 / 7 天，借款利息 25%，换盒费 $25 起，last sale 奖 $50 起。
- 提前还清的奖励先记成"剩余天数"，结算时折成局外的钱（M13 定公式）。
- 商店在 M9 才有；M8 的"打工那天还能买 perk"先只留流程上的位置。

任务，按顺序：
1. **局的状态**（`src/core/run_state.gd`）：层、天、债、期限；开局、过一天、一次还清、
   进下一层并利滚利、到期失败、第三层还清通关。纯逻辑加测试。
   同时记下这一局的统计（买票数、打工天数、借款、消费），结算和以后的成就都用它。
2. **局内账本**：`Economy` 的起始现金来自局的配置；账本多出工资、还款、换盒费、商店支出；
   恒等式跟着扩展。自由模式的规则和测试不动。
3. **打工**：占掉一整天，当天机器不卖票。工资来自一条涨薪曲线（数据），
   在固定的打工天数涨薪；界面只显示今天的工资，不显示曲线。
4. **LOAN**：基础额度按层上升，额度可被外部加成；借款和利息计入应还总额。
5. **关卡数据**：每个场景的票价、盒大小范围、奖表、换盒费、LOAN 基础额度；
   每层的债和天数。
   盒生成器从它取参数；自由模式仍然和 web 版逐位一致（golden 测试不动）。
   每层用哪个场景是一张可替换的表（为局外买的场景留位置）。
6. **换盒付费**：`MachineLogic` 换掉某一列的盒子，扣费，重新上货。
7. **Last sale 奖**：盒里最后一张票卖出时给额外奖，机器 LCD 提示。
8. **无头模拟器**（`tools/sim_runs`）：几种机器人（盲买、只打工、混合、借满）各跑大量的局，
   输出通关率和用掉的天数；断言只打工的机器人每层都在最后一天刚好还清、通关时余额为零，
   而少打一天工或花过一分钱就过不了。
9. **存档**：存档版本加一；剧情模式的局和自由模式分开存；局的种子。
10. **流程和界面**：菜单里选模式（自由、新的一局、继续）；每天开始时选进场还是打工；
    机器旁的债务、期限和 LOAN 读数；离场后的当日小结；开局变故和每次"利滚利"的剧情卡
    （先用文字，中英文）；一局结束的结算画面。
11. **驱动工具**：`tools/drive_run` 用合成输入打完一局，像 `drive_game` 那样逐帧查账。

**G 测：** 不带任何 perk 完整打一局：进场、打工、借钱、换盒、清盒尾拿 last sale、提前还款、到期失败。

### M9 技能与道具（已完成，等 G 测）
代码里的落法见 `docs/decisions.md` 的 M9 一节。做的时候定下来的几处（都可以改，数值全是占位）：
- **手机**：桌上右前方躺着一台碎屏手机（和左边的记事本对称），点它、按 P、按左上角的 PHONE 键，
  或者每天卡片上的 PHONE 键，都能拿出来；Esc 或 P 收起。手机开着时，桌子、机器和卡片都不响应。
  主屏三个 app：LOAN（金色）、SHOP（绿色）、CONTACTS（蓝色）；自由模式只有 LOAN。
  机器旁钞票面板上的 LOAN 键和卡片上的 LOAN 键都去掉了，卡片上原来的位置换成 PHONE。
- **商店随时能逛**：一局里任何时候都能打开（选进场还是打工之前、在机器前、打工之后、离场卡片上）。
  只用现金付，记进账本的"支出"，不能用机器里的 credit。
- **价格跟着层的倍率走**：目录里写的是第一层的价格，第二层乘 5、第三层乘 20，
  所以同一个 perk 在每一层都差不多值"几天的工资"。买过的 perk 整局都在。
- **perk tree**（`src/core/catalog.gd`，三列）：

  | 列 | perk | 每级效果 | 每级价格（第一层） | 前置 |
  |---|---|---|---|---|
  | 钱 | 肥奖 FAT PRIZES | 每个奖 +10% / +20% / +30% | 150 / 300 / 600 | |
  | 钱 | 好信用 GOOD CREDIT | 借款额度 +100 / +250 / +500（乘倍率） | 60 / 120 / 240 | |
  | 运气 | 手气旺 LUCKY STREAK | 新上机的亏盒有 25% / 50% / 75% 的机会被跳过，换成下一盒 | 120 / 250 / 500 | |
  | 运气 | 收尾人 CLOSER | last sale 奖 +100% / +200% | 80 / 160 | 手气旺 1 |
  | 读盒 | 熟客 REGULAR | 换盒费 -40% / -80% | 60 / 120 | |
  | 读盒 | 读盒 BOX READING | 见下 | 250 / 400 / 600 / 900 | 熟客 1 + 手气旺 1 |

  "手气旺"只在盒子上机的时候起作用（换盒、卖空、进下一层），已经在机器里的盒不变。
  被跳过的盒按种子定，所以同一个种子永远上同一盒，存档不受影响。
- **读盒四级**：指着（或刚按过）某一列时，机器显示屏第二行显示读数：
  1 级"约剩 650 张"（取整到 50）；2 级再加盒子的冷热（剩下的奖金除以剩下的票价：≥1.25 热，<0.8 冷，中间平）；
  3 级是准确的剩余张数和冷热，第三行和票名轮流显示剩下的大奖、中奖、小奖各几个；
  4 级记事本换成按盒记账：每一列这一盒已开几张、中了多少。读数只算还在机器里的票（卖出去的不算，开没开都一样）。
- **道具**（买了放在手机里，持有数显示在商店）：
  - 情报：偷瞄 PEEK（$20，看某一列接下来 10 张里有几张中奖）、盒子报告 BOX REPORT（$60，把某一列这一盒读到 3 级，换盒前一直有效）。
    这两个在商店里点 USE，手机收起，显示屏闪"选一列"，下一次按某一列的按钮就是读它，不卖票；按 PLAY ALL 取消。
    只能在机器前、进场的那天用。
  - 经济：幸运币 LUCKY COIN（$40，下一个中奖的票奖金翻倍，自动生效）。
  - 操作：换盒钥匙 BOX KEY（$15，下一次换盒免费，自动生效）。
- **联络人**：先放了两个占位的人。债主 THE LENDER 接电话，说你欠多少、还剩几天，卖一项服务

- **模拟器**（`tools/sim_runs`）多了一张表：买空整盒时每一美元票能回多少（含 last sale）。
  没有 perk 时约 1.00 到 1.04；肥奖满级约 1.30；手气旺满级约 1.12；肥奖、手气旺、收尾人全满约 1.56。
  另有一个"perks"机器人（每天早上买下一个 perk，只要价格不超过手里现金的一半），
  但它买得太少（大部分局在第一层就结束了），通关率和盲买差不多；这是数值那一步的事。

### M9.6 票种特性（第一层已完成，等 G 测；第二层待 G 挑规则）
G 提（2026-11-06）：票除了样式没有变化，要给不同票种赋予特性，让过程里的刺激多一点。
现状：八种票都是一块钱，共用一个盒生成器（`BoxModel`：大奖占比 0.10 到 0.40、中奖占比 0.10 到 0.25、
叠奖 0.12），期望回报一样；差别只在开法（整张中或按栏中、封条、翻面）和场景的机器卖哪几种。
所以"买哪一列"只由盒的状态决定，票种本身没有分量；perk 也只能写"所有奖 +X%"。
分两层做，先做第一层。两层都是票的 json 里的数据，效果从固定的菜单里选（和 perk 的钩子一样），
Workshop 的票包也能用。

**第一层：经济形状。** 期望不变（每种票盲买都约不赚不赔，否则就有"最优票"），分布不同。
真实的 pull-tab 就这么分：有的"一盒一个大奖"，有的"到处是小奖"。
盒生成器多一个 `shape` 参数（大奖占比、中奖占比、中奖票数的范围），写在票的 json 里：

| 票 | 形状 | 玩法 |
|---|---|---|
| Big Catch | 中奖少，顶奖大（1000），一盒最多一个 | 猎大奖、清盒 |
| Hot Plate、Nugget Rush | 到处是小奖（10、5），按栏中，方差小 | 稳着玩、吃亏流 |
| Lucky Spur | 中奖多在中档（200） | 平衡 |
| Ka-Bawk! | 要么大要么零，小奖也是 50，方差最大 | 一把全开、梭哈 |
| Pecking Order、One Flock、Peckeye | 先用默认，第二层给签名规则时再分 | |

- 票价也可以分档（一块、两块、五块，和真实机器一样，奖跟着涨）；先不做，数值那一步看要不要。
- **形状只在剧情模式生效**（G）：自由模式的盒照旧，golden 测试（Big Catch 和每盒的奖数与 web 版一致）不动。
  剧情模式的机器上货时把票种的形状交给盒生成器，自由模式不交。

**第二层：每种票一条签名规则**（Balatro 式），按名字来，每种只一条，只在这种票上生效，
第一层就能感觉到、不靠读盒。候选（G 挑、改）：

| 票 | 规则 |
|---|---|
| Big Catch | 顶奖出了之后，这一盒的 last sale 奖翻倍 |
| Hot Plate | 这一列连续中奖越热，下一张奖越大（每连中一张 +X%），输一张就凉 |
| Lucky Spur | 封条上印着这盒现在是冷还是热（内置一级读盒） |
| Pecking Order | 奖按顺序出：小奖出完才出中奖，中奖出完才出大奖，所以能数 |
| Ka-Bawk! | 中奖翻倍，但下一张必输 |
| One Flock | 一次连开里中奖的票过半，再加一个奖 |
| Nugget Rush | 没中的票也掉一块金块，攒够十块换这种票最小的奖，跨盒攒 |
| Peckeye | 看得见下一张中不中，但奖小一档 |

**每条规则两个把手**（G）：一个减负面或去前提（build 的一部分，比如保温让 Hot Plate 输一张不归零），
一个加正面（比如鱼群让 Big Catch 的 last sale 不要求顶奖出过，收尾人再叠上去）。
票种 perk 只在机器上有这种票时才发。整张表在 `docs/perk_research.md` 第五节 6b。

**票种变成选择**（有了特性才有意义，顺序靠后）：
- 换新盒时选放哪种票进这一列（场景卖的里面选）。

- 道具"往机器里加一种票"；局外解锁新票种（M13）。

代码里的落法见 `docs/decisions.md` 的 M9.6 一节。

  所以 `shape` 里再加 `prizes`：剧情模式里这种票的奖表。只在剧情模式生效，票面上印的也是它；
  自由模式的票和盒照旧，golden 不动。
